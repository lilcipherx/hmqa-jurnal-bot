# HMQA JURNAL BOT decision register

This register records product ambiguities and conflicts discovered while comparing the request, the Markdown PRD, and the DOCX product specification.

| ID | Topic | Evidence | Decision | Status |
|---|---|---|---|---|
| DEC-001 | Source priority | The request names the Markdown file as the primary source of truth and the DOCX as supporting visual/product material. | Product behavior follows the Markdown PRD. A DOCX-only value may inform presentation but cannot override Markdown behavior. | Accepted |
| DEC-002 | DOCX omissions | Normalized visible text is 99.6% aligned. The DOCX omits seven Markdown callouts/captions, including explicit Mini App and SUBMITTED-versus-ACCEPTED warnings. | The omitted Markdown statements remain binding. There is no active contradictory DOCX text. | Accepted |
| DEC-003 | Orphaned DOCX media | Four media files remain in the DOCX package but are not referenced by `word/document.xml`; one legacy diagram mentions a Mini App. | Orphaned package media is not treated as visible specification. The product contains no Mini App or WebApp author flow. | Accepted |
| DEC-004 | Workflow status names | The direct request lists `AUTO_CHECK`, `NEEDS_FIX`, and `EDITORIAL_SCREENING`; the source-of-truth PRD and visible DOCX diagram use `TECHNICAL_REVIEW`, `NEEDS_CORRECTION`, and `EDITORIAL_REVIEW`. | Persist only the PRD codes. Accept the three alternate names solely through an explicit legacy/import mapper. Never expose them as parallel live states. | Accepted |
| DEC-005 | Axborotnomasi bilingual manuscript packaging | PRD leaves one bilingual DOCX versus two DOCX files unresolved. | Seed Axborotnomasi as `CLOSED` with requirements in `DRAFT`. File rules remain configurable and cannot be published until the Academy selects a policy. | Open product decision |
| DEC-006 | Page-count authority | PRD leaves Microsoft Word pagination versus server render unresolved. | Preflight stores structural and rendered evidence. Page-count enforcement is configurable and defaults to warning until an approved renderer/tolerance is published. | Open product decision |
| DEC-007 | Reviewer model and four-eyes | Reviewer count, blindness mode, and approval policy are journal-specific. | The engine supports journal-scoped configuration. Seed values are disabled/default-safe and require published configuration. | Open product decision |
| DEC-008 | Retention and legal hold | Exact periods are not approved. | No destructive production retention job is enabled by default. Draft cleanup is configurable; submitted evidence requires policy plus legal-hold checks. | Open product decision |
| DEC-009 | Staff identity provider | Corporate OIDC/SAML provider is not specified. | Implement secure invitation-only local credentials with Argon2id, mandatory TOTP, and opaque server sessions. Production local authentication requires explicit enablement; OIDC remains an Academy integration decision. | Accepted technical default |
| DEC-011 | Runtime and dependency baseline | The request says Node.js 20+; current Next.js/Prisma releases support a newer maintained Node line. | Build and CI use Node 24.11.1 and pnpm 11.19.0 while keeping package engine compatibility at Node 20.19+. | Accepted technical default |
| DEC-012 | Notification delivery semantics | Telegram does not accept an application idempotency key for `sendMessage`. | Use at-least-once delivery, durable event IDs, single-winner DB claims, provider receipts, stale-claim recovery, and audited replay generations. A crash after provider acceptance but before receipt persistence may duplicate a message and is an explicit external limitation. | Accepted technical default |
| DEC-013 | Safe submitted-file formats | The PRD requires configurable allowed formats but does not define a universal executable-content policy. | The production ingestion path currently permits only DOCX and passive PDF, with category/format/size rules pinned in each published requirement version. Adding another format requires a validator and security review before the contract is expanded. Rejected evidence uses a separate encrypted private quarantine bucket. | Accepted technical default |
| DEC-014 | Submission receipt rendering | The PRD requires repeatable localized PDF receipts but does not prescribe a renderer or typography. | Persist an immutable locale-specific data snapshot in the submit transaction, render asynchronously with pdf-lib and embedded DejaVu Sans, store by content hash in private S3, and issue only audited owner/RBAC signed URLs. A receipt confirms technical delivery and never publication acceptance. | Accepted technical default |
| DEC-015 | DOCX formatting preflight | The PRD defines checks but leaves page-count authority and severities journal-specific. | Pin versioned rules in each requirement version, inspect bounded OOXML, render with headless LibreOffice in an isolated resource-limited worker, and persist codes/statistics without manuscript excerpts. The seed remains unpublished. | Accepted technical default |
| DEC-016 | Reviewer package creation | Blind-review mode and accountable anonymizer are not approved. | Provide an audited journal-scoped editorial upload for a separate derived DOCX/PDF, require manual attestation, run the full quarantine/ClamAV/S3 pipeline plus non-leaking PF-015 identifier checks, and never modify or expose the author original. | Accepted technical default |
| DEC-017 | Local external-provider verification | A production Telegram token and Academy infrastructure must not be fabricated, but lack of those credentials must not disable local acceptance. | Keep the default/production path on the real Telegram API and add a separate Compose override with an explicitly labelled test-only Telegram API fixture. The isolated runtime harness uses real PostgreSQL, Redis, MinIO, ClamAV and LibreOffice, fails on skips, performs fault injection and deletes only its validated project-scoped test volumes. | Accepted technical default |
| DEC-018 | Product access model override | The 2026-09-09 high-priority owner instruction conflicts with the PRD's former multi-role staff model and reviewer login. | The explicit later instruction wins: Telegram identities are authors, the Admin Panel exposes only multiple equivalent `ADMIN` accounts, and reviewers are standalone non-login contacts. Historical roles and links are archived by migration. See ADR 0009. | Accepted product override |
| DEC-019 | Privacy/audit visibility | Earlier specifications exposed Privacy and Audit as user navigation areas; the high-priority instruction removes privacy actions from Telegram and hides both areas from normal admin navigation. | Retain backend privacy, legal-hold, and immutable-audit controls, but expose neither Telegram privacy buttons nor normal Admin Panel Privacy/Audit navigation. | Accepted product override |
| DEC-020 | Current author profile | Earlier schema and flows included country, city, and ORCID; the high-priority instruction defines exactly seven conceptual author fields. | Current Telegram/API writes use full name, phone, email, organization, position, normalized degree, and normalized title. Legacy columns remain for data compatibility but are not shown or requested. | Accepted product override |
| DEC-021 | Configurable Telegram contacts | Earlier journal localization contained a free-form contact field; the owner now requires global and per-journal structured contacts. | Store phone/email/Telegram plus localized address/hours/note. Resolve populated journal overrides over the global record and then apply locale fallback. | Accepted product override |
| DEC-010 | Production hosting and secrets | Provider, domains, registry, vault, and on-call contacts are unknown. | Supply portable containers and deployment documentation. Production launch remains externally blocked until Academy-owned infrastructure and secrets are supplied. | External blocker |

## Required Academy approvals

- Product owner and journal owners.
- Official journal modes, codes, contacts, manuscript languages, fields, file rules, and deadlines.
- Axborotnomasi bilingual-file, page-count, taqriz, author-last-page, annotation, and keyword policies.
- Public privacy text, legal basis, consent version, retention, and legal-hold procedure.
- Reviewer model, decision authority, four-eyes policy, appeal/withdrawal policy, and SLA calendar.
- Approved translations and glossary for `uz-Latn`, `ru`, and `en`.
- Production infrastructure, domains, BotFather ownership, SSO policy, secret manager, and incident contacts.
